# LeanClaw 本机打包

LeanClaw 当前支持在 Apple Silicon Mac 上生成不依赖 Apple Developer 证书的本机包。构建使用 ad-hoc 签名：签名结构完整，但没有 Developer ID、Team ID 或 notarization，因此仅用于当前开发机自用和测试，不作为对外分发包。

## 生成本机应用

```bash
npm install
npm run package:mac
```

输出：

```text
release/mac-arm64/LeanClaw.app
```

可直接双击，或执行：

```bash
open release/mac-arm64/LeanClaw.app
```

## 生成 DMG 与 ZIP

```bash
npm run dist:mac
```

输出：

```text
release/LeanClaw-<version>-arm64.dmg
release/LeanClaw-<version>-arm64.zip
```

DMG 用于本机拖入 Applications；ZIP 用于保存完整应用副本，并为后续自动更新保留产物形态。`release/` 已加入 `.gitignore`，构建产物不提交 Git。

## 本地校验

单条命令跑完整套最终产物验证（T08 起为准）：

```bash
rm -rf release && npm run dist:mac && npm run verify:packaged
```

`npm run verify:packaged` 会：拒绝比源码更旧的产物（不允许复用旧包）→ 校验 DMG/ZIP 完整性与 SHA-256 →
从**解压后的 ZIP**取出被验证的二进制 → 核对应用版本、Bundle ID、Electron 版本与 native ABI →
断言签名仍是 ad-hoc（出现签名机构会失败关闭，提示配置漂移）→ 在隔离数据根首启并跑核心 Journey →
用 T06 的 old-binary v8 fixture 验证**最终 `.app` 的旧库升级**，最后打印两个 SHA-256。

需要单独复核时的原始命令：

```bash
codesign --verify --deep --strict --verbose=2 release/mac-arm64/LeanClaw.app
hdiutil verify release/LeanClaw-0.1.0-arm64.dmg
unzip -t release/LeanClaw-0.1.0-arm64.zip
```

`verify:packaged` 通过只等于 `Packaged smoke pass`。当前签名是 ad-hoc、未公证、未接入 updater，
不得写成正式发行、`Release ready` 或 `Shipped`。

当前配置：

- Bundle ID：`com.leanclaw.desktop`
- 架构：arm64
- 签名：ad-hoc（`identity: "-"`）
- Hardened Runtime：关闭
- notarization：无
- 原生模块：`better-sqlite3` 在打包时按 Electron 43 / arm64 重建并从 ASAR 解包
- 图标资源：复制到 `Contents/Resources/resources`，运行时通过 `process.resourcesPath` 解析

## 边界

- 从互联网传到其他 Mac 后仍可能被 Gatekeeper 拦截；正式分发需要 Developer ID Application 签名与 Apple notarization。
- 当前只构建 arm64，不包含 Intel x64 或 universal 包。
- 自动更新尚未接入；需要确定更新源后再加入 `electron-updater`。
- 本机包已携带 Electron 运行时，不依赖首次启动时动态下载 Electron。
