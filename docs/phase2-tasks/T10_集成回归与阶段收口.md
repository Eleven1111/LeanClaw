> 状态：✅ 完成并通过用户最终验收

## 1. 目标

证明 Agent、Activity、Runtime、Need You 和 Automation 不是五个孤立页面，而是一条可靠、兼容、安全的本机工作流。

## 2. 端到端验收旅程

### 旅程 A：Agent 正常交付

1. 创建 Agent；
2. 从 Agent Center 发起任务；
3. 默认 Recipe/预算带出；
4. Task 固化快照；
5. Activity 显示 Agent 开始、Step、Approval；
6. Need You 处理批准；
7. Delivered；
8. Activity 显示交付；
9. Runtime 统计增加。

### 旅程 B：Agent 修改不污染历史

1. Agent A 创建 Task；
2. 修改 Agent 名称和指令；
3. 旧 Task/Activity 仍显示 snapshot；
4. 新 Task 使用新配置；
5. 停用 Agent 后旧 Task 可回看，新 Task 不可选择。

### 旅程 C：异常处理

依次注入：

- Tool 连败 → Andon；
- bad citation → verification failed；
- expensive model → budget stop；
- provider primary 500 → fallback。

每次确认：

- Activity 正确；
- Need You 正确；
- Runtime 状态诚实；
- 处理后从检查点继续或明确取消。

### 旅程 D：自动化

1. 创建绑定 Agent 的 Automation；
2. 立即运行；
3. 定时运行；
4. 两次都进入普通 Task；
5. 历史可回看；
6. 失败进入 Need You；
7. 暂停不影响已创建 Task。

### 旅程 E：旧数据库升级

从真实 v8 副本启动：

- 旧 Task/Run/Artifact/Evidence/Event/Schedule 数量不变；
- 旧 Task 显示默认执行器；
- 新建 Agent 后可正常使用；
- 归档事件摘要正常；
- 应用可重启。

### 已知风险与验收边界

- 未配置 Apple Developer ID 与 notarization；当前产物是有效 ad-hoc 签名，不是已公证发行版。
- `npm audit` 剩余 2 个 moderate：`@hono/node-server` 的 Windows `serve-static` 编码反斜杠路径遍历；自动全修会强制降级 MCP SDK，未采用 `--force`。本阶段 macOS 本机 stdio MCP 路径不暴露该静态文件服务。
- 1000 Task 的首次完整 View 水合约 8.4 秒，虽未冻结且列表保持窗口化，但仍是下一阶段应优先消除的 N+1 性能债。
- v8 回归由历史列定义重建 fixture，并非独立保存的生产副本；未知外部手改索引/约束不在证明范围。
- UI 矩阵以专项 E2E 合并覆盖空态、错误、offline/degraded、20+ 数据等状态；单个九页面截图用例没有对每一页穷举所有状态组合。
